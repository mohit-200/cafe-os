# Decisions

| # | Decision | Alternatives considered | Trade-off / reason |
|---|---|---|---|
| D1 | Build a **web app with Gemini features**, not an ADK agent | ADK agent on Cloud Run or Agent Runtime | Availability, waits and seating must be deterministic and auditable. The LLM only extracts intent, so an agent adds cost, latency and evaluation surface without adding value. |
| D2 | Make **Declared Departures / Visit Ledger** the core differentiator | Crowd/noise prediction alone | Crowd and noise apps already exist (Brew Finder, SpotCheck, SoundPrint). A forward seat-time signal for walk-in cafés appears unaddressed. |
| D3 | **Four line labels**: prediction, suggestion, confirmed, café rule | Single "plan" with implied promises | Honest UX. Cafés can't guarantee seats or noise. "Café rule" marks facts from café configuration, not model output. |
| D4 | **One Cloud Run service** serving the API and the static web app | Firebase Hosting + Cloud Run | One deploy and one URL. Both are free at demo scale. |
| D5 | ~~Realtime listeners in the browser~~ → **short polling (2–3 s) of an in-memory read model, only while the tab is visible** | Firestore client listeners, SSE/WebSockets on Cloud Run | *Changed in Phase 3.* SSE keeps a Cloud Run instance billed for as long as a tablet stays open: a café board open 12 h/day exceeds the free tier (≈ $25+/month), which breaks the $5 cap. Polls are ~10 ms requests (≈ 0.5 vCPU-hours/month per open board), return "unchanged" when nothing moved, and never touch the database because they hit memory. |
| D6 | **No BigQuery, Pub/Sub, Scheduler or Maps** in the MVP | Including them for "architecture points" | Not needed yet. Each has a clear trigger for adding it (see DESIGN §G). |
| D7 | Gemini **`gemini-3.1-flash-lite` on the Vertex AI global endpoint**, temperature 0, JSON schema, daily cap (300) | `gemini-3.5-flash-lite`, Flash/Pro, regional endpoint | *Chosen by eval in Phase 4:* the 2.5 models return 404 in this project (retired). 3.1 Flash-Lite scored 22/22 (100%) with prompt v2 vs 95.6% for 3.5 Flash-Lite, and it's the cheaper of the two. About 1 s per request. Results: `evals/RESULTS.md`. |
| D8 | Staff recommendations are **rule-based and templated**, not LLM-written | Gemini-written insights | No hallucinated operational advice. Zero cost. |
| D9 | Customers stay anonymous: a **signed visit token** (HMAC) proves ownership of a visit. Raw text is redacted and kept 24 h. | Firebase anonymous auth, accounts | *Changed in Phase 3.* Same privacy outcome with no Firebase SDK, config or extra service. |
| D10 | **Python 3.12 + FastAPI** backend, **no-build vanilla JS** frontend (ES modules) | TypeScript monorepo; React/Vite | *User choice: Python.* There's no Node toolchain, so the Dockerfile stays tiny and the planner lives in one language. The UI is small enough that a framework isn't needed. |
| D11 | **Single instance** (`--max-instances=1`, one uvicorn worker), live state cached in memory, **written through to Cloud SQL**, reloaded on cold start | Stateless multi-instance with a database read on every poll | Polling stays free (D5), and one café easily fits one instance (80 concurrent requests). To scale to many cafés, shard cafés across instances or add a shared cache or notification channel between instances. |
| D12 | **Staff sign-in = shift PIN → 12 h signed token**. PIN and signing key come from **Secret Manager**. | Firebase Auth email/password with custom claims | *Changed in Phase 3.* Matches how cafés actually work (a shared tablet). Login is rate limited to 6 per minute per IP. Per-person accounts are on the roadmap if a café wants an audit trail. |
| D13 | **One-tap order sending** with the visit confirmation, pay at counter, no payment data | Recommend timing only; full ordering | *User choice.* The tap is the explicit human approval. Staff move it through Start → Ready → Collected. Staff can pause phone orders from an alert. |
| D14 | **Rule-based intent parser as the fallback** for Gemini (off, error, timeout or cap reached) | Gemini only | The app is fully usable with Gemini off, locally or if the cap is hit. Gemini adds robustness to messy phrasing. |
| D15 | **Demo clock** (`DEMO_START=14:30`) pins café time for a predictable demo | Real time | Rehearsals behave identically whatever the real hour, and the café is never "closed" on stage. Leave it unset for real use. |
| D17 | **Cloud SQL for PostgreSQL replaces Firestore** (PostgreSQL 17, Enterprise, `db-f1-micro`, 10 GB SSD, zonal, backups, deletion protection), **always on, paid from hackathon credits** | Firestore free tier; Cloud SQL stopped between demos | *User requirement (stack: Cloud Run + Cloud SQL + Gemini).* Costs about $9–10/month, over the original $5 cap. Paid from the Google Cloud free credits. The budget is $15/month measured *before* credits (`--credit-types-treatment=exclude-all-credits`); with the default (after credits) it would never fire and credit burn would be invisible. The Visit Ledger is a real `visits` table (key columns + JSONB), ready for SQL analytics. The 24 h privacy retention is enforced by the app (purge on load and expiry in memory) instead of a Firestore TTL. Connection uses the Cloud Run built-in Cloud SQL connector (Unix socket, no public authorized networks), with the DB password in Secret Manager. |
| D16 | Re-plan alternatives must have **better seat odds than staying put**, falling back to the best others | Show the top-scored alternatives | Offering an equally full zone is noise, not help. |
